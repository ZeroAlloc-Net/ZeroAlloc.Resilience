# ZR0006 — Policy Not Applied to Method

**Severity:** Warning

Since 3.0 the proxy forwards methods the interface inherits from a base interface, and they get the interface-level policies. Before 3.0, an inherited method with a default body was not forwarded, so its default body ran. Some policies cannot be applied to such a method without a build error. For those, the generator forwards the method without that policy, so the interface keeps compiling, and reports ZR0006 so it is clear the method is not protected by it. The method's other policies still apply.

The policy can come from an attribute on the proxied interface, or from the inherited method's own attribute in the base interface. The message says which, and where to fix it.

A policy is left off in these cases:

| Policy | Method returns | Why |
|---|---|---|
| `[RateLimit]` | `ValueTask<Result<T, E>>` or `Task<Result<T, E>>` with an `E` other than `ResilienceError` | a rejected call must return a failure, and the generator cannot build an `E` |
| `[CircuitBreaker]` without a matching `Fallback` | the same | the open circuit must return a failure, and the generator cannot build an `E` |
| `[Retry(NonThrowing = true)]` | anything but `Result<T, ResilienceError>` or `UnitResult<ResilienceError>` | exhausted retries must return a `ResilienceError` failure |
| any policy | an async type, with a `ref`, `out`, `in` or ref struct parameter | an async method cannot have them; every policy is left off, and the method is forwarded without `async` |
| any policy | by `ref` or `ref readonly` | a policy-wrapped method cannot return a reference to the inner result; every policy is left off, and the method is forwarded as `=> ref ...` |

On a method the interface declares itself, or an inherited abstract method, which the proxy has to implement, the same cases are errors: [ZR0003](ZR0003.md), or [ZR0007](ZR0007.md) for the last two rows.

## Own methods the proxy does not implement

ZR0006 is also reported for a method the interface declares itself that the proxy does not implement, when a policy would apply to it. Its policies have no effect, and in 2.0 the proxy did apply them:

| Method | Why the proxy does not implement it | Policies reported |
|---|---|---|
| `string ToString()`, `bool Equals(object)` or `int GetHashCode()` | `object`'s own member implements it on the proxy, so the proxy keeps its own equality | its own attributes, and the interface-level ones |
| a `sealed` method | no class can implement it; a call runs its interface body | its own attributes |
| a `static` or non-public method | a proxy instance cannot implement it | its own attributes |

```csharp
// ZR0006: Method 'ToString' on 'IReport' is not implemented by the proxy, so it runs without
// [Retry], because it has the signature of object.ToString, so object's own ToString implements
// it on the proxy. Remove [Retry] from 'IReport.ToString'.
public interface IReport
{
    [Retry(MaxAttempts = 3)]
    string ToString();

    ValueTask RenderAsync(CancellationToken ct);
}
```

To have the policy apply, give the method another name, such as `Describe`.

## Example

```csharp
public interface IQuotes
{
    ValueTask<Result<decimal, QuoteError>> GetQuoteAsync(string symbol, CancellationToken ct)
        => ValueTask.FromResult(Result<decimal, QuoteError>.Success(0m));
}

// ZR0006: Inherited method 'GetQuoteAsync' on 'IQuoteService' is forwarded to the inner service
// without [RateLimit], because a rejected call must return a failure, and the generator cannot
// build the error type 'QuoteError' of 'Result<decimal, QuoteError>'. Remove [RateLimit] from
// 'IQuoteService' and put it on the methods that need it, or declare 'GetQuoteAsync' on
// 'IQuoteService' with a return type the policy supports.
[Retry(MaxAttempts = 3)]
[RateLimit(MaxPerSecond = 10)]
public interface IQuoteService : IQuotes
{
    ValueTask RefreshAsync(CancellationToken ct);
}
```

`GetQuoteAsync` is retried, but not rate-limited.

---

## How to fix

Declare the method on the interface with a return type the policy supports. It is then the interface's own method, and the policy applies:

```csharp
[Retry(MaxAttempts = 3)]
[RateLimit(MaxPerSecond = 10)]
public interface IQuoteService : IQuotes
{
    new ValueTask<Result<decimal, ResilienceError>> GetQuoteAsync(string symbol, CancellationToken ct);
    ValueTask RefreshAsync(CancellationToken ct);
}
```

Or, if the method should not have the policy, remove the attribute from the interface and put it on the methods that need it. For a circuit breaker, a `Fallback` that matches the method's signature also resolves it.
