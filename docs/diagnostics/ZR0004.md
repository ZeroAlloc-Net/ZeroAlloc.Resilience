# ZR0004 — Invalid Policy Attribute Value

**Severity:** Error

A policy attribute sets one of its properties to a value the runtime policy constructor rejects with `ArgumentOutOfRangeException`. Rather than let the interface compile and throw the first time its `{Name}ResiliencePolicies` is constructed, the generator reports ZR0004 at build time and emits no proxy for the interface.

Only properties that are explicitly set on the attribute are checked. A property left at its default is always valid, since the default itself satisfies the rule.

The rules, matching the runtime policy constructors exactly:

| Attribute | Property | Rule |
|---|---|---|
| `[Retry]` | `MaxAttempts` | at least 1 |
| `[Retry]` | `BackoffMs` | at least 0 |
| `[Retry]` | `PerAttemptTimeoutMs` | at least 0 |
| `[Timeout]` | `Ms` | greater than 0 |
| `[CircuitBreaker]` | `MaxFailures` | at least 1 |
| `[CircuitBreaker]` | `ResetMs` | at least 0 |
| `[CircuitBreaker]` | `HalfOpenProbes` | at least 1 |
| `[RateLimit]` | `MaxPerSecond` | at least 0 |
| `[RateLimit]` | `BurstSize` | at least 0 |

An interface-level attribute is reported once for the interface, not once per method. A method-level attribute is reported on that method. Two invalid properties on the same attribute produce two diagnostics, one per property.

---

## Example

```csharp
// ZR0004: MaxAttempts must be at least 1, but is 0
[Retry(MaxAttempts = 0, BackoffMs = 200)]
public interface IJevApi
{
    ValueTask<string> ModelsAsync(CancellationToken ct);
}
```

---

## How to fix

Set the property to a value that satisfies the rule. For `MaxAttempts`, that means at least 1:

```csharp
[Retry(MaxAttempts = 1, BackoffMs = 200)]
public interface IJevApi
{
    ValueTask<string> ModelsAsync(CancellationToken ct);
}
```

If several properties are invalid, ZR0004 reports each one, so fix them together and rebuild.
