# ZR0014 — Policy Not Supported on a Stream Method

**Severity:** Error

A method that returns `IAsyncEnumerable<T>` takes `[Retry]` alone, and is retried only until its first item. See [Streams](../core-concepts/retry.md#streams). ZR0014 is reported at the attribute when the stream method's own attributes ask for anything else:

| Attribute | Why a stream cannot apply it |
|---|---|
| `[Timeout]` | The timeout would have to cancel the stream while the consumer reads it. |
| `[Retry]` with `PerAttemptTimeoutMs` above 0 | The same, for each attempt. A `PerAttemptTimeoutMs` of 0 is not set, and is not reported. |
| `[CircuitBreaker]`, with or without `Fallback` | Whether a stream succeeded is known only once the consumer has read it to the end, and a failure after the first item is not the proxy's to count. |
| `[RateLimit]` | A rejected stream could fail only once the consumer starts reading it, not at the call. |

The same policies on the interface, or on an inherited method's declaration, are [ZR0015](ZR0015.md), a Warning, and are left off the stream method.

---

## Example

```csharp
public interface IMessagesApi
{
    // ZR0014 error: [Timeout] cannot apply to 'StreamAsync', because it returns
    // IAsyncEnumerable<T>: a stream method takes [Retry] alone, without PerAttemptTimeoutMs,
    // and is retried only until its first item. Remove [Timeout] from 'StreamAsync'.
    [Retry(MaxAttempts = 3)]
    [Timeout(Ms = 30_000)]
    IAsyncEnumerable<MessageEvent> StreamAsync(MessageRequest request, CancellationToken ct);
}
```

---

## How to fix

- Remove the attribute from the stream method. Keep `[Retry]` without `PerAttemptTimeoutMs`.
- To bound how long the consumer reads, cancel the token passed to the method or to `WithCancellation`, for example with `CancellationTokenSource.CancelAfter`.
