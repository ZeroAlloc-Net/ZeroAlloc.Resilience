# ZR0013 — RethrowDeclined Has No Effect

**Severity:** Warning

`[Retry(RethrowDeclined = true)]` rethrows an exception that `RetryOnException` declines, unchanged, instead of wrapping it in `ResilienceException`. See [Declined exceptions and `RethrowDeclined`](../core-concepts/retry.md#declined-exceptions-and-rethrowdeclined). ZR0013 is reported at the `[Retry]` attribute when the property can change nothing:

| Case | Why it has no effect |
|---|---|
| The `[Retry]` has no `RetryOnException` | No exception is ever declined: every exception is retried. |
| A method-level `[Retry]` on a method returning `Result`, `Result<T>`, `Result<T, ResilienceError>` or `UnitResult<ResilienceError>` | The method returns a failure instead of throwing, for a declined exception too. |
| An interface-level `[Retry]` whose methods all return one of those types | The same, for every method it applies to. A method with its own `[Retry]` does not count, because that attribute shadows the interface's. |

An interface-level `[Retry]` over a mix of methods is not reported. The property works on the methods that throw, and the Result methods need no change. Reporting them would leave no way to silence the warning except moving the `[Retry]` onto every throwing method.

A `Result<T, E>` with any other error type `E` cannot hold the exception, so it throws, and `RethrowDeclined` applies to it.

---

## Example

```csharp
// ZR0013 warning: [Retry] RethrowDeclined = true has no effect on 'IOrdersApi', because the
// [Retry] has no RetryOnException, so no exception is ever declined.
[Retry(MaxAttempts = 3, RethrowDeclined = true)]
public interface IOrdersApi
{
    ValueTask<Order> GetAsync(string id, CancellationToken ct);
}

public interface IInventoryApi
{
    // ZR0013 warning: ... has no effect on 'ReserveAsync', because it returns a failure instead
    // of throwing, for a declined exception too.
    [Retry(RetryOnException = nameof(IsTransient), RethrowDeclined = true)]
    ValueTask<Result<Reservation, ResilienceError>> ReserveAsync(string sku, CancellationToken ct);

    static bool IsTransient(Exception exception) => exception is not ArgumentException;
}
```

---

## How to fix

- Without `RetryOnException`: set `RetryOnException` to choose which exceptions to retry, or remove `RethrowDeclined`.
- On methods that return failures: remove `RethrowDeclined`. The declined exception is already in the failure. With `Result<T, ResilienceError>` it is the `ResilienceError`'s `InnerException`.
